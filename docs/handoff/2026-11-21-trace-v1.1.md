## 2. สิ่งที่รอ commit (PLAN-005) และวิธี commit

มีไฟล์ protected (`scripts/sdlc_guard/**`, `.claude/settings.json`, `.codex/hooks.json`, `docs/contracts/trace-event.schema.json`) จึงต้องให้ **human** commit ด้วย `SDLC_ALLOW_PROTECTED=1` (agent ตั้งตัวแปรนี้ไม่ได้ตามที่ออกแบบ):

```bash
git add -A
SDLC_ALLOW_PROTECTED=1 git commit -m "feat: trace v1.1 with model/effort, local timestamps, more hook events and level control"
git push
```

- ข้อความ commit ต้องเป็น Conventional Commits (commit-msg hook ตรวจ)
- หลัง push: release-please จะเปิด **Release PR เสนอ `0.2.0`** (ถูกต้อง เพราะนับจาก tag `v0.1.0`) · PR ของ bot **ไม่ trigger CI ปกติ** (ข้อจำกัดของ `GITHUB_TOKEN`) จึงควรอ่านก่อน merge
- Codex: ไฟล์ `.codex/hooks.json` เปลี่ยน ต้อง review/trust ใหม่ด้วย `/hooks`

## 4. การตัดสินใจที่ตกลงกันแล้ว (และเหตุผล)

| เรื่อง | ตัดสินใจ | เหตุผล |
| :--- | :--- | :--- |
| Schema version | คง `v: 1`, เพิ่มเฉพาะ field optional | ยังไม่มีข้อมูลเก่าที่ต้อง migrate; อ่านไฟล์เก่าได้ |
| เวลา | `ts` = เวลาเครื่อง + offset; `SDLC_TRACE_TZ=utc` ทางเลือก | ผู้ใช้ต้องการ UTC+7; offset ทำให้ Elastic/Loki/OTel อ่านเป็น instant เดียวกัน |
| ควบคุม level | env > `.sdlc/trace.json` > `info` | ไม่พึ่ง `env` ใน settings เพราะเอกสารไม่ยืนยันว่าส่งเข้า hook |
| Agent เปลี่ยน level | ได้เฉพาะ `debug --for ≤120m` และเปลี่ยนค่าที่ human ตั้งไม่ได้ | กัน agent ปิด/ลด audit ของตัวเอง |
| `SDLC_TRACE_*` ไม่อยู่ใน override ที่ห้าม agent ตั้งใน command | ตัดออก | การตั้งใน Bash tool ไม่มีผลกับ hook (Claude spawn hook เอง) จึงเป็นแค่ false positive |
| Hook ที่ trace | Tier 1 เป็นค่าเริ่มต้น, Tier 2 opt-in | คุมปริมาณและ overhead |
| ห้าม trace | `WorktreeCreate`, `WorktreeRemove`, `MessageDisplay`, `Setup` | WorktreeCreate แทนที่พฤติกรรม git; MessageDisplay ยิงทุก delta |
| Trace hook | เงียบ, exit 0, `async` | ไม่ไปเปลี่ยนผลของ hook ที่ตัดสินได้ (PermissionRequest, ConfigChange, PreCompact) |
| `.claude/settings.json` | **generated** โดย `sync-adapters` | กัน drift ระหว่าง Claude / Codex / tests / docs; ค่าส่วนตัวให้ใส่ `settings.local.json` |
| Release | release-please + Conventional Commits | ตัวเลือกที่ผู้ใช้เลือก |
| Trace storage | local, ไม่ commit | privacy; commit ได้เฉพาะ summary ที่ `export` |

## 5. ยืนยันแล้ว vs ยังไม่ยืนยัน

**ยืนยันกับของจริง**
- Claude Code ส่ง `effort` เป็น object `{level}` และมี `prompt_id`, `permission_mode` (เห็นใน event จริง)
- Claude โหลด hook ใหม่กลาง session (เห็น event `ConfigChange` ที่เกิดจากการ regenerate settings)
- `stdin.isatty()` เป็น `False` ใน Bash tool ของ Claude → ชั้น TTY ของ `config set` ใช้ได้กับ Claude
- Windows CI รัน test เขียน trace พร้อมกันผ่าน (รอบ PLAN-004)

**ยังไม่ยืนยัน (ต้องตรวจต่อ)**
1. **`model` ยังไม่เคยเห็นค่าจริง** — session ปัจจุบันเริ่มก่อนมีการบันทึก SessionStart จึงเป็น `unknown` → เปิด session ใหม่แล้วรัน `python3 scripts/sdlc_trace.py list` ถ้ายังเป็น `unknown` แปลว่า Claude ไม่ส่ง `model` ใน hook ให้พึ่ง `PostModelSwitch` หรือ OTel
2. ตัวอย่าง Grafana Alloy / Filebeat / OTel Collector / OpenSearch template **ยังไม่ได้ทดสอบกับ stack จริง**
3. Codex: payload จริง, ฟิลด์ `async`, ขีดจำกัด background hook (เอกสารว่าราว 8; ตอนนี้ลงทะเบียน async 9 ชนิด), TTY ใน Codex, exit code และ `token_usage` ย่อยของ `tool_response`
4. Windows: test ใหม่ (state write, TTY, config) และ CI smoke step ใหม่ ต้องรอ CI หลัง push
5. เอกสาร Claude ไม่ระบุรูปแบบ `tool_response` ของ Edit/Read และ Bash แบบเต็ม (ใช้ stdout/stderr ตามที่เห็นจริง)

## 6. ข้อจำกัด / ความเสี่ยงที่รู้อยู่

- Trace เป็น **audit aid ไม่ใช่ tamper-proof**: agent หลักยังแก้ `.sdlc/trace.json` หรือลบ `.sdlc/` ได้ (`.sdlc/**` protected เฉพาะ role dev); ไม่มี hash chain
- Guard วิเคราะห์ command แบบ best-effort: script ที่เขียนก่อนแล้วรันทีหลัง (`tee x.sh <<EOF … && sh x.sh`) หลุดได้ ด่านสุดท้ายคือ pre-commit + CI + branch protection (**ยังไม่ได้ตั้ง branch protection / CODEOWNERS**)
- กฎ deploy production จับจากข้อความ → false positive กับคำสั่งอ่านอย่างเดียว (`grep "deploy production"`)
- `redact` ครอบคลุมรูปแบบที่รู้จัก ไม่ใช่ทุกกรณี; prompt ของผู้ใช้ถูกบันทึก (หลัง redact)
- Hook ถี่ขึ้น = Python spawn มากขึ้น (ส่วนใหญ่ async); Windows รัน test ได้ช้ากว่า (~43 วินาที) ถ้าช้าขึ้นอีกให้ดู
- `hooks enable/disable` รองรับ Claude เท่านั้น (Codex `PreModelRequest` ยังไม่ทำ)

## 7. Gotchas สำหรับผู้รับช่วง

1. **Test ต้องไม่เขียนลง trace จริง:** subprocess ที่เรียก `sdlc_hook.py pretooluse/session-start/trace` ต้องตั้ง `SDLC_TRACE_LEVEL=off` หรือ `SDLC_TRACE_DIR` ชี้ temp (เคยทำให้เกิด session `unknown` ปนใน store จริง)
2. **Guard ทำงานกับ session ของ agent เอง:** ข้อความที่ดูเหมือนการตั้ง `RELEASE_APPROVAL` / `SDLC_ALLOW_PROTECTED` / `SDLC_GUARD_FAIL_OPEN` ที่ต้นคำสั่งจะถูก block (ข้อความใน quote/heredoc ข้อมูลไม่ถูกนับ); เขียนไฟล์ด้วย Write tool แทนการยัดเนื้อหาใน heredoc ที่ส่งเข้า shell
3. **ห้ามแก้ `.claude/settings.json` / `.codex/hooks.json` ด้วยมือ** — แก้ที่ `scripts/sdlc_guard/trace_hooks.py` หรือ `scripts/sync-adapters.py` แล้วรัน `python3 scripts/sync-adapters.py --sync`
4. เพิ่ม event/field ใหม่ในที่เดียวให้ครบ: `trace.py` (mapping) → `trace-event.schema.json` → test (`test_schema_file_matches_validator` เทียบ enum) → คู่มือ
5. ไฟล์ที่ protected ต้องให้ human commit; commit message ต้อง Conventional Commits
6. ตัวชี้วัดสุขภาพ: `python3 scripts/doctor.py`, `python3 scripts/sdlc_trace.py config show`, `python3 scripts/sdlc_trace.py list`
